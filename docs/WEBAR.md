# WebAR parallax window

The GitHub repository contains three implementations of a photograph reconstructed with Apple's SHARP: native iOS (`ios/`, ARKit and MetalSplatter), Mattercraft (`mattercraft/`, Zappar and Spark), and WebAR (`src/ar/`, 8th Wall, Three.js, and Spark). WebAR is the development target. Mattercraft's multiple-window placement is separate from the single-window WebAR experience; the sweep-band and periphery effects are shared through its shader graph files.

## Run and review

Run `npm install` if needed, then `npm run dev`. Vite serves HTTPS on port 5174 for phone camera and motion access. The engine copy step runs automatically and preserves the bundled 8th Wall engine and license.

- `/ar.html`: phone experience. Start AR, allow camera/motion, move slowly forward and back until scale calibration completes, then tap anywhere on the camera view to place the photograph in front of you. Placement uses the phone's horizontal heading and XR8's estimated world ground (`y=0` in absolute scale); it never waits for a surface hit. The final portal stands on that estimated ground and rises 4 m; the ground may differ from the physical floor if tracking is inaccurate. Tap the photograph or **tap to activate memory** below it. Reset clears the placement and restores the original for the next placement.
- `/memory.html`: camera-free preview of the **same** activation controller and splat modifier. Tap to play. Tuning controls are hidden by default; add `?controls=1` for the timeline, scene controls, and particle-flow sliders. Replay restores the dormant photograph.
- `/index.html`: existing camera/framing tuning preview.

AR and memory preview accept `?splats=full|50|25` (default `50`) and `?fx=none|band|periphery|band,periphery`. AR also accepts `?dpr=1` and `?debug=1` to show tracking/render diagnostics. Diagnostics are hidden by default; camera, placement, activation, and error prompts remain available. Memory preview accepts `?t=1.15` to freeze a stage on load and `?fxTime=3` to freeze the ambient sweep phase for comparisons.

Both pages accept `?sceneDistance=-2.03&spillStrength=6.3&spillAngle=31&spillSoftness=60` (see **Street placement** and **Ground spill** below) and `?depthStretch=1&parallaxGain=1`. Depth stretch ranges from 0.5 to 4; parallax strength ranges from 1 to 4. The memory preview also provides live sliders for both. Both default to 1×, which keeps the street's proportions. Depth stretch scales distances behind the portal plane along its normal, keeping the street's ground on the floor. Parallax strength is a camera-dependent shear of the street behind the portal; it makes distant content follow the phone, so it is not physical. Larger gains consume SHARP's limited viewing baseline faster, so its reconstruction quality still limits extreme viewpoints.

`?flatEffectStrength=0.25` scales dreamlike effect changes during the flat stage (range 0–1, default 100%). The **Flat dream effects** slider provides the same live control: 0% disables the flat-stage modulation and 100% reproduces the previous full-strength behavior. Size growth/shrinkage, brightness boost, and opacity reduction are interpolated from their neutral values, so reducing strength does not shrink or darken the base image. The gain smoothly reaches 100% as depth opens; the final 3D effect tuning is unaffected.

The **Particle flow** panel at `/memory.html?controls=1` provides eight live sliders. **Preview ripple** repeats just the color transition; **Pause ripple** holds its current frame. Scrubbing the activation timeline or pressing Replay ends the loop. Editing a slider while outside the color stage starts the ripple preview automatically. Reset restores only the flow settings, and Copy link saves a reproducible tuning URL with the current inspected frame and scene controls. On small screens the panel moves into the scrollable bottom card; collapse it to access the scene controls.

| Parameter / URL key | Default | Range | Effect |
| --- | --- | --- | --- |
| `particleCount` | 11,516 | 0–60,000 | Number of spray particles; 0 hides the spray. |
| `particleSizeMin` | 3.4 px | 0.2–24 px | Smallest particle at the crest. |
| `particleSizeMax` | 5.1 px | 0.2–24 px | Largest particle at the crest. |
| `rippleDiameter` | 1.01 (101%) | 0.5–2.5 | Maximum circular ripple diameter relative to the photo diagonal. |
| `transitionWidth` | 0.14 (14%) | 0.04–0.6 | Width of the particle crest and color reveal; scales with the photo diagonal. |
| `flowStrength` | 0.35× | 0–3× | Amount of particle drift, lift, and surface refraction. |
| `flowSpeed` | 1.55× | 0–3× | Speed of swirling and turbulence; the 2.7-second color sweep keeps its timing. |
| `rippleTurbulence` | 1.75 (175%) | 0–2 | Irregularity of the circular front; 0 gives a smooth circle. |

The size boundaries carry each other along when crossed so minimum never exceeds maximum. All eight URL parameters also work on `/ar.html`. The spray reuses a fixed particle buffer and changes its draw count; every density prefix covers the whole image. Diameter, width, strength, speed, and irregularity update the shared photograph/splat/particle wave together. Even a small diameter or broad transition finishes revealing the full photograph smoothly before expansion.

## Live phone tuning and preparation

The phone AR view has a collapsed **Tune** button. The menu docks below a resized camera canvas, rather than covering the memory; closing it restores the full camera area. Canvas resizing updates the XR camera projection and render buffer together. Tuning gestures are handled by the panel and never trigger placement or activation.

In portrait the sliders use two columns with a scrollable area. In landscape, the dock rearranges into four columns and keeps a usable slider area. Resize writes run on the next animation frame to avoid resize-observer errors when opening, closing, or rotating the view.

- **Layout:** image width, distance, height offset from the placement-time phone; portal width, height, and distance. The portal always stands on the estimated ground.
- **Scene:** scene size, scene distance, ground spill, spill angle, spill edge blur, depth stretch, parallax strength, and flat-stage dream effects.
- **Particles:** the eight particle/ripple parameters listed above.
- **Timing:** color, flat hold, and depth durations.

**Original** restores the dormant photograph at the existing placement; **Replay** plays the full activation; **Loop ripple** repeats the color stage. The activation scrubber holds any frame while the ambient effects continue animating. **Defaults** restores the shared preset, and **Copy link** includes all 25 tuning values without a frozen playback/effects clock. All parameters work as URL keys on AR and memory preview. The address bar follows the tuning at most every quarter second, because Safari throws an error past 100 address updates in 10 seconds, which dragging a slider used to reach. The same phone dock can be reviewed without a camera at `/memory.html?arControls=1`.

Layout and scene tuning update transforms and shader uniforms; they do not rebuild the splat generator, shader, or particle buffers. Photo geometry scales its existing UV-mapped plane, and the shared physical dimensions update the photograph, splats, particle wave, aperture, and tap target together.

First-use work happens before activation: photographs and SOG data load first, then the actual GL renderer warms the color, depth, and final states offscreen. Preparation awaits Spark's generation/sorting, `renderer.compileAsync`, texture uploads, and a WebGL2 GPU fence. The AR camera feed and tracking can run while this happens, with a **Preparing memory effects…** prompt; scene rendering/placement/activation wait until preparation succeeds. In preview it happens before the activation button or scrubber becomes available. A preparation error leaves activation disabled and visible errors intact. Uniform-only tuning does not need another shader warmup. The dormant splat mapping stays resident at zero reveal after placement so replay can reuse the prepared resources.

Placement primes the dormant mapping again before enabling activation. It drains any queued automatic update or in-flight sort first, waits for the placed mapping's sorting to finish, and uploads its ordering texture before the GPU fence. This prevents Spark's early-returning `update()` from making activation ready while a prior sort still runs. `npm test` covers readiness/failure handling, overlapping sorts, placement-time anchoring, the floor-standing street, tuning endpoints, and uniform-only shader reuse.

## Memory activation

`input/apalabassa-original.jpg` is the supplied black-and-white photograph of the south side of Apalabassa St. (300 to 320), copied without modification. Vite bundles it as a hashed asset; `photoUrl` selects it.

`input/apalabassa.jpg` is the restored color photograph used for the SOG reconstruction (`output/apalabassa/`, assets in `src/scene-assets.js`). `colorPhotoUrl` selects it for the activation surface and particle spray. Each particle carries its originating pixel's color while its motion varies. The surface's chromatic refraction samples neighboring RGB channels from this image, and the splats retain their own reconstruction colors. There is no generated pink/cyan palette. Update this color asset when changing the reconstruction.

The stages are controlled by `src/memory-settings.js`:

1. **Dormant:** full photograph at 0.2 m wide, preserving its proportions, **0.4 m horizontally ahead of the phone at placement**. Its center is at that phone's placement-time height. An instruction is projected below the image, and the splat scene is hidden. The anchor remains fixed when the phone moves.
2. **Color (2.7 s):** a wide, irregular circular wave travels from the center in physical coordinates, independent of photo aspect. The photograph refracts and dissolves through its own restored colors; an 11,516-particle spray curls around the crest. The actual colored splats are revealed on a thin sheet behind the window. Ambient sweep/periphery effects begin with the first colored region at the configurable flat-stage strength.
3. **Surface hold (0.35 s):** the colored reconstruction stays flat before opening.
4. **Depth (3.1 s):** a quintic minimum-jerk curve starts slowly, accelerates, and slows to a stop. The aperture grows to **1.6 m wide × 4 m tall**, **3.44 m horizontally ahead of the placement-time phone pose**, standing on the estimated ground. Splats move into the street. Their inverse depth and image rays interpolate with the same eased progress as the aperture. The aperture itself recedes from 0.4 to 3.44 m in inverse depth and moves vertically along that shared viewing-ray interpolation, keeping it in front of the street behind it throughout expansion. Its size grows in viewing angle, as the rays do; growing it in metres while it receded in inverse depth made it balloon to about twice the final portal's apparent size halfway through. Ground that ends up in front of the portal pours out onto the floor as the portal opens.

**Street placement.** The settled street is the reconstruction itself at its captured, approximately metric scale. `scripts/fit_ground.py` fits SHARP's street ground: the photographer's level camera was 1.70 m above it, and the reconstructed street begins 3.78 m ahead. The street is levelled onto the estimated floor along the placement heading. **Scene distance** (`sceneDistance`, −3 to 12 m, default −2.03 m) is the distance from the portal plane to where the street begins. Lower values bring the whole street closer, which strengthens parallax without changing its scale; the viewer stands where the photographer did when it equals `captureGroundStart` × Scene size − Portal distance (about −0.23 m with the defaults). Below zero, the street's ground passes through the portal onto the floor in front of it. **Scene size** (`sceneScale`, default 0.85, tuned on a phone) scales about the street's start, keeping it on the floor. Moving closer magnifies the nearest content, so SHARP's single-photo detail limits how close the street can come.

**Ground spill.** The street in front of the portal spills out like daylight through a doorway, keeping its splats as they are. The lit area is a fan whose edges leave the portal's sides at half the **Spill angle** (`spillAngle`, 20–170°, default 31°). Like a penumbra, the edges are a smooth sigmoid with soft tails that widens the further it is from the portal, by the **Spill edge blur** angle (`spillSoftness`, 0–80°, default 60°). Brightness falls off with distance as the form factor from the floor to the opening does, through an exposure curve set by **Ground spill** (`spillStrength`, 0–8×, default 6.3×): it is full at the threshold and rolls off smoothly instead of clipping into a flat plateau; 0 cuts the street at the portal plane. About 1.5 nearly opaque SHARP splats overlap at each point of the ground (1.2–1.7 across the three assets), so the modifier shares the light's optical depth among them equally rather than fading each splat by the light, which would compound into harder edges; per-splat shares made neighbouring splats fade unevenly. The spill is evenly 15% brighter than the street, the street's cut-off front edge fades in with a C2 curve over most of the spilled strip, and the spill never reaches behind the placement point. Everything in front of the portal spills, ground or not, so at low Scene distance whatever stands near the street's front edge enters the fan. Splats that settle hidden fade out early in the expansion instead of crossing the room. While the aperture recedes, ground bound for the floor just in front of the portal is still behind it, so the matte would hide it below the opening and leave a gap. Such splats are held just in front of the aperture during the expansion, slid along the viewer's line of sight so their place and size on screen are unchanged.

The matte occludes each splat at its centre's depth only, so a large splat just behind the portal could paint past the opening onto the floor in front of it. The modifier drops splats behind the aperture whose centres the viewer cannot see through it, every frame; the matte trims the rest per pixel.

The GPU modifier changes uniforms during activation instead of uploading new splat buffers each frame. It transforms covariance with the spatial mapping's Jacobian, preserving each Gaussian's projected footprint instead of separately mixing thin scales and orientations. This fixes gaps during expansion; a small temporary overlap reserve also protects the decimated samples. Spark's covariance renderer and extended precision retain the resulting shapes and positions. This uses more GPU memory than the checkpoint's packed renderer, so mobile performance needs verification. The photo, splats, and particle spray share the same wave. Aperture growth scales the existing matte instead of rebuilding geometry each frame.

The desktop preview includes a floor grid and adjusts its review camera to the current aperture distance and center as the portal opens, keeping the larger result visible. Its camera framing uses the same current frame as the geometry. The phone retains 8th Wall's calibrated projection. Because the settled street is placed rigidly, ambient effects use the live camera directly once depth opens.

Depth uses `1 / mix(1 / sheetDepth, 1 / targetDepth, growth)` during expansion. Interpolating metres had made distant background splats reach most of their visible parallax change while the aperture had barely grown. The new mapping interpolates the perspective quantity that controls apparent depth; its analytic derivative also drives the covariance transformation, keeping splat footprints coordinated with their centers. The flat shell and fully expanded scene retain their exact endpoint mappings. Its inverse-depth progression equals the aperture's eased progression. `src/memory-placement.js` uses the same inverse-depth/viewing-ray mapping for the moving aperture, from `photoDistance` and `photoElevation` in `src/memory-settings.js` to the floor-standing portal at `portalDistance`.

Flattening every splat onto exactly the same depth destroys its foreground/background blend order. Spark sorts by distance to the viewer; a coplanar image therefore becomes smeared even with `fx=none`, then abruptly sharpens as the first depth movement restores ordering. The flat stage uses a shallow camera-centered shell: each splat stays on the viewing ray through its anchored photograph pixel, while its hidden distance increases with its original capture distance. The covariance follows the same mapping, so its projected footprint is preserved. This retains the capture's blend order while the image looks flat, then smoothly interpolates to the 3D mapping at the final portal position. The flat-stage gain separately controls the actual sweep/periphery modulation.

`captureAspect` and `captureFocalRatio` describe **the color photograph that produced the SOG**, not the original. Current values match `input/apalabassa.jpg` at 1448×1086 and SHARP's assumed 30mm focal length (1255 px, recorded in the PLY's intrinsics). `captureGroundUp`, `captureCameraHeight`, and `captureGroundStart` describe its street, from `.venv/bin/python scripts/fit_ground.py output/apalabassa/apalabassa.ply`. Update them all if the reconstruction changes. To rebuild the assets: `.venv/bin/sharp predict -i input/apalabassa.jpg -o output/apalabassa --device mps`, then PlayCanvas `splat-transform` with `-d 50%` and `-d 25%` into `output/apalabassa/decimated/`, and each PLY to `public/apalabassa{,_50,_25}.sog`.

## Build and delivery

`npm run build` produces `dist/`, including the AR page, both previews, original photograph, and unmodified 8th Wall engine. SOG files under `public/` are currently ignored by Git. This feature uses the existing SOG assets; it does not regenerate them.

The production project is `chinatown-splat-ar`, served at `https://chinatown-splat-ar.vercel.app`. Its root opens AR with the chosen defaults and a dormant photograph; the tuning URL's `t=0.86` inspection frame is not a playback default. `/ar.html` is also available directly.

For a complete release, link the existing project with `vercel link --yes --project chinatown-splat-ar`, run `npm run vercel:prepare`, then `vercel deploy --prebuilt --prod`. The preparation script verifies all three local SOGs before building, copies only `dist/` into Vercel's static Build Output API structure, and routes `/` to `/ar.html`. This includes Git-ignored scene/engine assets without uploading source folders, local credentials, or development captures. A source-only/Git rebuild must supply the SOG assets separately. The packaged engine keeps its resources and license intact.

Desktop browser verification covers the shader compilation, all activation stages, tap hit testing, sideways viewing, reset/replay, and a 390×844 viewport. Actual mobile camera tracking, Safari rendering, and frame rate require a device check. Existing GitHub and Vercel terminal sessions are used for sync and publication; only an expired or missing login needs user interaction.

To check the flat/depth boundary, load `/memory.html?controls=1&t=3&fxTime=3&flatEffectStrength=0.25` and scrub between 3.0 and 3.2 s. Also compare 3.05 and 3.06 s, immediately around expansion's start. Repeat with `&fx=none` to isolate splat ordering from ambient effects and use the sideways slider to check that the flat image stays anchored when the viewing direction changes.

## WebXR tracking and App Clips

`/ar.html` chooses its tracker when it loads. If the browser offers WebXR `immersive-ar`, the page runs a WebXR session and the host's native tracking drives the camera: ARCore in Chrome on Android, or ARKit inside an iOS App Clip that adds WebXR, such as Needle Go. Otherwise it loads 8th Wall as before; Safari on iPhone has no WebXR AR. `?tracking=webxr` or `?tracking=xr8` forces one, and `?debug=1` shows which one is running on the `tracker` line.

On iPhone, open the page through Needle Go's App Clip: `https://appclip.needle.tools/ar?url=` followed by the URL-encoded page address. Needle's App Clip is already published, so it needs no Apple setup, and page changes deploy to Vercel as usual without an App Store review.

Under WebXR the host draws the camera behind a transparent canvas, and `#ar-ui` is the session's DOM overlay, so the prompts, buttons and tuning dock stay usable. The floor is `local-floor`'s y = 0 when the host grants it. Otherwise it is the first surface hit straight below the session's starting point, or 1.45 m below that point until a surface is found. Memory preparation finishes before Start is enabled: while a session presents, three.js renders every frame with the XR camera, including the warm-up renders. 8th Wall's engine is not downloaded on this path, and its credit line is hidden.

On the dev server, `/ar.html?xremu=1` installs the IWER WebXR emulator (a dev dependency) so the WebXR path runs in a desktop browser. The emulator raises its own view over the page while presenting, so script taps on `#ar-tap` to place the memory. Vite drops this code from production builds.
